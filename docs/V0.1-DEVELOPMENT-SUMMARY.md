# VERO Studio V0.1 development summary

## Foundation

Studio uses Electron, React, and Vite, matching the proven desktop distribution approach in the available VERO GFX reference while remaining a separate application. Electron provides a secured local HTTP origin, the Local Bridge/vMix proxy, Windows packaging, and an updater boundary. React supports the operator workspace without coupling integrations to UI components.

The application is divided into configuration, versioned production types, persistence, state/actions, components, and modular Bridge/vMix/GFX/account integrations. No GFX files were modified and no broad shared package was created. The supplied official VERO Studio icon, wordmark, and combined lockup are used across the application and Windows installer.

## Reused VERO patterns

- Electron with context isolation, sandboxing, single-instance behavior, and NSIS packaging.
- `/__vero/bridge/health` for Bridge discovery and `/__vero/vmix` for private-LAN vMix proxying.
- vMix XML validation/state parsing and Local Bridge failure states.
- Dark premium operator UI, restrained product accent, persistent settings, and visible connection health.

## Implemented

- Versioned Production schema with stable IDs and references for accounts, workspaces, events, teams, graphics, configurations, and ecosystem connections.
- Local production index, active-production selection, settings storage, migration entry point, create/open/reopen flow, and persistence tests.
- Startup shell and responsive production workspace with Preview, Program, transition controls, input grid, Inputs, Audio, Graphics, Connections, and Settings pages.
- Bridge health monitoring and automatic recovery polling every 2.5 seconds.
- Real vMix XML input discovery, Program/Preview synchronization, external-change detection, input-to-Preview selection, CUT, Fade-based AUTO, volume, and mute commands.
- Accurate disabled/offline UI, reusable severity alerts, failed-command reporting, and no simulated feeds or meters.
- Account and GFX integration boundaries that return unavailable states rather than fake identities or successful commands.
- Replay and VERO Audio connection placeholders; future multiview/rundown fields can attach to Production without changing switching actions.
- Centralized app/endpoints/version configuration and an Electron updater boundary configured for `JacobPhelan1/vero-studio-releases`. Installed builds check automatically, download updates in the background, and install them safely on exit.

## Limitations and follow-up

- The requested `vero-gfx` sibling was not in the workspace. `vero-dashboard`, which contains VERO GFX, supplied the read-only reference.
- Bridge input thumbnails depend on paths/URLs returned by vMix; no thumbnail proxy is currently added.
- vMix meter levels are not available in the current Bridge contract and are not simulated.
- AUTO currently maps to vMix `Fade` with the saved duration. Transition discovery/type configuration needs a future Bridge contract.
- GFX needs an authenticated discovery/capability/command protocol before quick controls can be enabled.
- The shared account backend must expose secure desktop authentication, entitlement, workspace membership, and session contracts. Studio stores no credentials today.
- Auto-update publishing requires the GitHub release repository, release token secret, and eventually a trusted Windows code-signing certificate.
- Production data currently uses durable browser storage under Electron's user-data directory. A future native file/database service should add atomic backups, export/import, and cloud synchronization.

## Recommended V0.2 priorities

1. Extend the shared Bridge with typed state/capability versioning, thumbnail proxying, audio meters, transition discovery, and explicit command acknowledgements.
2. Define authenticated VERO application discovery and GFX production-context/quick-control protocol.
3. Connect the VERO Account and organization backend with entitlement-aware desktop sessions.
4. Add atomic production export/import/backups and schedule-event ingestion.
5. Run switching and reconnect integration tests against an actual vMix machine, then add multiview and rundown foundations.
